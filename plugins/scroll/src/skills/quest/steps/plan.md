# ① 설계 — `plan.md`

## 할 일

1. 첫 행동은 설계가 기대는 코드 사실 재기: 대상 수, 바뀔 규칙 문장 grep(규칙 문서·스킬·README 모두), 부딪힐 가드(빌드 가드·구조 시험·흐름 가드), 고정된 명세. `## 잰 코드 사실`에 `- <명령> → <결과>`.
2. `## 결정`: 결정마다 선택지 둘 이상·권장·이유·틀렸을 때 비용·근거(규칙 ID·결정 번호·패턴). 애매한 결정 하나만 먼저 보고 싶으면 그 결정을 쓰자마자 코드 전 검토 리뷰어(`step plan-review`가 내주는 안내 — `{MODE}` = `decision <id>`, 보고 `agents/plan-reviewer-<id>.md`)에 백그라운드로 보낸다. `## 결정` 절을 다 쓰면 커밋 `<ID> plan: 결정`하고 바로 `step plan-review`를 불러 전체 리뷰어를 띄운다(리뷰어가 도는 동안 3을 쓴다).
3. `## 할 일`: 번호를 붙여(`- [ ] N. …` — 이 꼴이 아닌 목록 줄이 있거나 할 일이 0개면 끝 확인이 막는다) 할 일마다 고정할 시험(이름·자리, 가드면 심을 위반)을 적는다. TDD가 맞지 않는 일(문서만 등)은 이때 그 줄에 `TDD 예외 — <까닭>`(코드 전 검토 뒤에 붙이면 `## 구현하며 바뀐 것`에 `할 일 N`과 까닭). 커밋 `<ID> plan: 할 일`.

## 쓰는 틀

- `${CLAUDE_PLUGIN_ROOT}/src/skills/quest/templates/plan.md` → `<작업 폴더>/plan.md`. 요구사항은 `<작업 폴더>/requirements.md`(리드가 커밋해 둔 것 — 고치지 않는다).

## 지킬 것

- 첫 `test` 커밋 앞의 `plan`·`plan-review` 커밋은 구현 파일(시험 파일·기록 폴더·`.md` 밖)을 건드리지 않는다(끝 확인이 막는다).
- 결정 번호는 요구사항 머리의 범위만 쓴다.

## 마치는 조건
