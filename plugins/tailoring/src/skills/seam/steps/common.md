## 모든 단계에서 — 작업 세션 <ID>

- 단계마다 먼저 `python3 "${CLAUDE_PLUGIN_ROOT}/src/scripts/seam/main.py" step <단계>`를 부르고 나온 안내를 따른다. 앞 단계 커밋이 없으면 멈추고 무엇을 먼저 할지 알려 준다. 앞 단계로 되돌아가기(예: 코드 전 검토 뒤 다시 `step plan`)는 된다.
- 커밋은 `git commit -m "<ID> <단계>: …"`로만 한다 — 커밋하는 순간 PreToolUse 훅이 제목 꼴(이 작업 ID·작업 세션 단계·`run`의 할 일 번호 `#N`), 앞 단계 커밋, 그 단계를 `step`으로 들어왔는지를 본다. 편집기를 여는 커밋·`-F`·`-C`/`-c`·`--fixup`은 막힌다. 커밋이 없는 단계는 `git commit --allow-empty -m …`.
- 스스로 결정·기록하며 끝까지 간다. 결정하는 법: ① 확정 규칙(`<안내 문서>`의 규칙 색인에서 찾은 규칙 문서) → ② 과거 결정(`<결정 폴더>`) → ③ `<안내 문서>`에 사용자 결정 패턴이 있으면 그것 → ④ 그 위에서 비판적으로(선택지 둘 이상·권장·이유·틀렸을 때 비용). 결정 파일은 다음 작업도 따를 판단일 때만 `<결정 폴더>`에(머리 `작업: <ID>`, 요구사항의 결정 번호 범위 안).
- 규칙 문장(규칙 문서의 문장·규칙 ID 줄)은 멈추지 않고 스스로 정해 고치고, "바뀐 규칙 문장" 확인이 켜져 있으면(설정 `seam.rule_docs`에 꼴이 있으면) `retro.md` `## 바뀐 규칙 문장`에 한 줄씩 남긴다 — `<규칙 파일>:<규칙 ID 또는 절> · <옛 문장> → <새 문장> · <까닭(결정 번호)>`. 리드는 기다리지 않고 합치고 합친 뒤 보고에 그 목록을 올리며, 고칠 것이 있으면 다음 작업으로 고친다.
- 리드에게 전달(`SendMessage`): 도구 목록에 안 보이면 `ToolSearch`(`select:SendMessage`)로 먼저 불러온다. 실패하면 한 번만 더 해 보고, 그래도 안 되면 지시 장부(`.seam-session/orders.md`)에 그 전달을 열린 줄로 적고 `| 대기: 리드 — 전달 실패`를 붙인 뒤 일은 이어 간다 — 전달 실패는 `retro.md` `## 어긋난 것`에도 한 줄, 그 줄이 열린 채 턴을 끝낼 때는 `남은 지시:`에 그 전달을 적는다(Stop 훅은 대기 사유가 붙은 열린 줄을 받는다).
- 사용자에게 묻지 않는다. 사용자가 정할 자리(되돌릴 수 없는 일 — 삭제·푸시·병합 / 확정 규칙끼리 충돌 / 요구사항 뒤집힘) 셋만 결정 요청: `<작업 폴더>/asks-<n>.md`(물음, 선택지·권장·이유·비용·근거) 커밋 → 리드에게 `[<ID> → <리드>] 결정 요청: <경로>`(SendMessage) → 30분 안 깨우기 예약(ScheduleWakeup `delaySeconds` ≤ 1800 또는 CronCreate — 보냄 뒤에 없으면 Stop 훅이 되돌린다) → 마지막 줄 `대기: 리드 — 결정 요청`. 기다리는 동안 할 수 있는 일은 먼저 한다. 답 `[<리드> → <ID>] 결정: <n> <고른 것>`이 오면 asks 파일 끝 `## 결정`과 `plan.md` `## 결정`에 `리드 전달(사용자 결정 <날짜>)`.
- deny가 막은 명령은 스크립트·인터프리터로 돌아가지 않는다 — 되돌릴 일은 커밋으로 하고, 커밋 나누기·가지 옮기기처럼 막힌 일이 꼭 필요하면 리드에게 `[<ID> → <리드>] [막힘] <막힌 명령과 까닭>`을 보낸다. deny와 훅은 OS 경계가 아니다(같은 사용자 권한).
- 기록은 `<작업 폴더>/`의 `plan.md`·`review.md`·`retro.md`(틀은 `${CLAUDE_PLUGIN_ROOT}/src/skills/seam/templates/`), 리뷰어 보고는 `<작업 폴더>/agents/<이름>.md`. 넘길 일 장부 `<장부>`와 작업 목록 `<작업 목록>`은 고치지 않는다(리드가 합칠 때).
- 단계 시각은 `python3 "${CLAUDE_PLUGIN_ROOT}/src/scripts/seam/main.py" status <ID>`. 슈퍼파워 `brainstorming`·`writing-plans`·`executing-plans`·`finishing-a-development-branch`와 할 일별 기록(progress.md 등)은 쓰지 않는다.
